# תרגיל 2: התיאור השבור

**זמן: שתי דקות. אין כאן קוד לתקן.**

## מה עושים

ב-`src/tools/toolDefinitions.ts`, מחליפים את התיאור של `search_documents`
בתיאור הזה:

```ts
description: 'search',
```

מריצים מחדש (`tsx watch` יטען לבד) ושואלים:

```json
{ "message": "What are my open tasks?" }
```

## מה קורה

בגרסה המקורית התיאור אמר במפורש:

> Do NOT use this for questions about the user own tasks.

בלי המשפט הזה, המילה `search` היא הכי כללית שיש. לשאלה "מה המשימות
הפתוחות שלי" יש בה את הרעיון של חיפוש, ולכן המודל עלול לבחור דווקא
בכלי המסמכים.

**מה שתראו בפועל אינו קבוע.** לפעמים המודל עדיין יבחר נכון, לפעמים לא,
ולפעמים יבחר אחרת בהרצות שונות של אותה שאלה. גם זה חלק מהשיעור:
ההחלטה עברה למודל, והיא לא דטרמיניסטית.

## איך לוודא מה נבחר

מוסיפים שורה אחת ב-`agentService.ts` אחרי הקריאה הראשונה:

```ts
console.log('TOOL:', first.functionCalls?.[0]?.name)
```

עכשיו רואים בטרמינל מה נבחר בכל הרצה. הריצו את אותה שאלה שלוש פעמים.

## מה להחזיר בסוף

את התיאור המקורי. ואז להריץ את אותה שאלה שוב, ולראות שהיא חוזרת
ל-`list_tasks`.

## המסקנה

> ה-`description` אינו הערה. הוא הקוד שמנתב את המערכת.

תלמיד שמבין את זה יכתוב תיאורים טובים לבד. תלמיד שלא, ידבג שעה
את `executeTool` בזמן שהבעיה נמצאת במחרוזת.
