## איך לעבוד עם זה בכיתה

**אל תחלק את התיקייה הזאת מראש.** תן קודם את `server/` בלבד, ותן להם לנסות.
אחרי שכל זוג ניסה, פותחים את הפתרון ומשווים.

הסדר שאני ממליץ עליו: **תרגיל 2 קודם**, למרות שהוא השני ברשימה.
הוא לוקח שתי דקות ומוכיח שהתיאור הוא קוד ולא הערה — ואחרי שהם הפנימו את זה,
תרגיל 1 (כתיבת כלי חדש) יוצא להם הרבה יותר טוב.

## תרגיל 1: `complete_task`

הכי חשוב בתרגיל הזה **אינו הקוד** אלא השאלה שבסופו:
מאיפה המודל יודע מהו ה-`task_id`?

התשובה: הוא לא יודע. הוא חייב קודם לקרוא ל-`list_tasks`, לראות את המזהים,
ורק אז לקרוא ל-`complete_task`. כלומר **שני כלים ברצף** — וזה בדיוק מה
ש-`runAgent` הנוכחי לא יודע לעשות, כי הוא מריץ כלי אחד ועוצר.

לכן התרגיל הזה מסתיים בתסכול מכוון, והוא הגשר למפגש 2.

**הפתרון בתיקייה כולל שתי דרכים לעקוף את זה** בלי לולאה מלאה:

1. לזהות משימה לפי **כותרת** במקום לפי מזהה (`complete_task_by_title`).
2. לגרום ל-`list_tasks` להחזיר את המזהים בתוך הטקסט, כך שהמשתמש יוכל
   לבקש בהודעה הבאה.

הראשונה עובדת יפה בכיתה. השנייה מדגימה למה הקשר בין הודעות דורש זיכרון,
וזה שוב מוביל למפגש הבא.
